第五章 APRS 报文处理与转发

报文进来之后：检查什么、怎么分发、源呼号怎么算，以及数据留不留。

5.1 报文格式 SERVER 应尽可能兼容所声明支持的 APRS-IS 文本报文格式。报文处理应遵循相应的 APRS 格式规则，不得假定所有报文均具有完全相同的结构。

5.2 报文检查 SERVER 应对接收报文执行必要的格式、长度和异常输入检查。对于非法报文、超长输入或明显异常的报文速率，可以拒绝处理，并在必要时记录安全事件。

5.3 报文转发 通过必要检查的报文，应根据转发规则和客户端订阅条件进行分发。转发过程应避免重复处理相同报文，并限制待发送队列大小，防止异常客户端占用过多资源。

5.4 源呼号管理 客户端登录时声明的呼号与报文中的源标识应分别处理。白名单授权不自动证明客户端提交的所有报文均真实来自对应的无线电发射设备。

如需限制客户端使用的报文源标识，应制定明确的报文授权规则。

5.5 内存转发 SERVER 的实时转发应以流式处理为主，尽量避免不必要的报文持久化。但内存转发不代表系统完全不存在数据留存：日志、监控及其他运行组件仍应遵循明确的数据处理规则。
