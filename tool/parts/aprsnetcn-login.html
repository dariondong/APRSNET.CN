登录行怎么写

关键字和顺序都照 APRS-IS，末尾多出 auth 与 filter 这两段。

登录行是一行纯文本，关键字后面跟参数。只有 user 和 pass 必须填，其余可以省，顺序不能换。

  • 格式 user 呼号[-SSID] pass passcode vers 软件名 版本 [auth 账号 口令] [filter 条件] auth 后面两段是名单里的账号与口令，由服务器发给你；filter 后面可以带空格。
  • 一个只收的例子 user BG7XXX-9 pass -1 vers APRSLocus 2.1.10 auth 账号 口令 filter r/22/114/200 末尾让服务器把北纬 22 度、东经 114 度两百公里内的台站推过来。

auth 必须写在 filter 前面。filter 把后面所有词都当成过滤条件，写在它后面的账号口令服务器根本看不到，连接就成了没带账号的那一种。

名单按主呼号查一条记录，SSID 共用同一条。名单里没有这一条就进不来。有效期过了，被停用，同样进不来。

  • user 呼号与 SSID。SSID 可以省，省掉等于 0，不写 -0。
  • pass 算出来的 passcode。-1 表示只收不发。
  • vers 软件名与版本号，各写一个词。
  • auth 名单账号与口令。名单里那一行设了口令才用得上。
  • filter 服务器端过滤器，写法与APRS-IS 过滤器一样。

服务器先看登录行格式，再看呼号，然后校验 passcode，接着查名单，最后核账号口令。哪一步没过就断开，先回一行 # logresp 呼号 unverified, server APRSNETCN，再回一行原因，例如 # aprsnetcn: not authorized (auth-failed)。看到 auth-failed 就对着名单再核一遍账号口令。

名单里那一行设了口令、登录行却没带 auth，连接只收不发。认下来之后服务器回的是 # logresp 呼号 verified, server APRSNETCN，只收的那一种是 unverified。
