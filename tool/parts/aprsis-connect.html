连上 APRS-IS

用法就一件事：拿一个客户端，连到某台服务器的一个端口上。端口选哪个，决定你能收到多少、以及能不能发。

APRS-IS 是互联网那一侧的那张网：世界各地的服务器互相转发收到的包，你只要连上其中一台，就等于站在整张网里：收得到别人的包，验证通过之后，自己发的包也会被转发出去。每台服务器都有状态页，用浏览器打开 http://服务器地址:14501，它开了哪些端口就一目了然。

  • 14501 HTTP 状态页。javAPRSSrvr 系的服务器在这上面还可能顺带开着 HTTP 只发端口与 WebSocket。
  • 10152 TCP 全量 feed：所有包都推给你。每秒几十个包，带宽很快顶满，多数客户端撑不住，别长期挂着；真要接，先想清楚拿来干什么。
  • 14580 自定义过滤 feed，日常最常用。默认只给你「发给你的消息」和「你的网关收上来的包」，其余靠 filter 命令一条条加，写法见APRS-IS 过滤器。这是双向端口：验证通过后你发的包也会进 APRS-IS（FireNet 的服务器除外）。
  • 23000 TCP 全量 feed，但客户端必须在登录行里声明自己收包的 UDP 端口。核心服务器都支持。
  • 8080 HTTP 和/或 UDP 只发端口，标准 HTTP 端口；javAPRSSrvr 系在这上面还支持 WebSocket。

两个常踩的坑：双向客户端连 APRS-IS 时要关掉 Nagle（TCP_NODELAY），不然收发会明显延迟；只想先看看、不打算发射，也要用自己的呼号，passcode 填 -1 就表示只收。

本页根据官方的 Connecting to APRS-IS 整理。端口和参数跟着官方走，措辞按中文习惯重写。要填一遍，见先在手机上听那一节。
