第三章 客户端接入规范

从 TCP 连接、登录行写法，到服务器依次检查什么、什么情况下拒绝。

3.1 连接方式 客户端通过 TCP 连接 APRSNET CN SERVER。正式服务应公布服务器域名、端口及必要的连接参数；客户端必须使用指定的 APRSNET CN 接入地址。

3.2 登录格式 客户端使用兼容 APRS-IS 的登录格式。

  • 基本登录行 user <呼号> pass <Passcode> 最常用的形式。
  • 带客户端版本 user <呼号> pass <Passcode> vers <客户端名称> <版本号> 在支持客户端版本字段时使用。

3.3 登录校验 SERVER 收到登录请求后，应依次执行以下检查。

  1. 检查登录指令格式。
  2. 检查呼号格式。
  3. 执行当前登录模式要求的 Passcode 校验。
  4. 查询本地白名单。
  5. 检查授权状态及有效期。
  6. 决定是否允许接入。

未通过必要检查的客户端不得进入正常报文交换阶段。

3.4 Passcode 机制 APRSNET CN 保留传统 APRS-IS Passcode 的兼容性设计。

Passcode 校验与白名单授权属于两个独立环节。Passcode 不应被视为完整的身份认证机制，也不能替代白名单准入。

服务器必须明确其实际采用的校验策略，不得在未声明的情况下改变传统登录格式的含义。

3.5 拒绝接入 以下情况应拒绝接入。

  • 格式错误 登录格式错误。
  • 呼号非法 呼号格式非法。
  • 校验失败 必需的登录校验失败。
  • 不在名单 呼号不在有效白名单中。
  • 授权状态 授权已经过期、暂停或撤销。
  • 安全问题 连接违反明确的安全限制。

拒绝接入时，SERVER 应根据兼容性要求返回适当响应或关闭连接，不得向客户端泄露内部管理信息。
